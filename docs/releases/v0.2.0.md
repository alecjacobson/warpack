# v0.2.0 — supported fast block solves

The fast pure-Warp Anvil path is now part of the installed library. It combines
`BatchedSparseOperator`, `BatchedCGPreconditioner` and explicit `BlockLOBPCG`
options for cached operator images and device-selected CG/search widths.
Existing solver defaults are unchanged. FEM assembly, reference comparisons,
rendering and host file I/O remain outside the installed solver package.

The package also includes the work accumulated since v0.1.3: constrained and
generalized block solves; finite right modes of regular generalized complex
pencils; original-equation acceptance checks; replay fixes for changed sparse
values, constraints and transposes; upstream CG/GMRES diagnostics; and the
normal-product SVD and projected-eigensolve improvements documented in the
README. This is an expanded API release, not a claim of complete ARPACK,
Spectra or CuPy conformance.

## Install and reproduce the fast Anvil solve

Base installation requires Python >=3.10 and Warp >=1.15. The fast batched-CG
path additionally requires the pinned upstream Warp modules below. The ordinary
install does **not** provide them. Stock Warp 1.15 exposes `batch_offsets` but
lacks the required `max_batch_length`; the fast adapter explicitly rejects it. cuDSS is optional and is not used in this path.

From a source checkout of this release on Linux x86-64:

```bash
python -m pip install '.[test]'
python -m pip install --no-deps --target build/warp-fsai \
  'https://github.com/NVIDIA/warp/releases/download/v1.18.0/warp_lang-1.18.0%2Bcu12-py3-none-manylinux_2_28_x86_64.whl'
python scripts/install_fsai_overlay.py build/warp-fsai
PYTHONPATH="$PWD/build/warp-fsai:$PWD" OPENBLAS_NUM_THREADS=4 OMP_NUM_THREADS=4 \
  python -m examples.anvil_block --out build/anvil-block.json
```

The installer checks the target's Warp version and verifies SHA256 hashes of
all three upstream files before writing any of them. They are unmodified files
from revision `04427b997fe7ff07bc6ed1dde5ca9813496c6b55` of
[the upstream FSAI PR](https://github.com/alecjacobson/warp/pull/16).
The wheel provides Warp 1.18.0+cu12; no driver changes are needed on the tested
CUDA 12.8 / driver 570.158.01 machine. Conditional graphs require a driver
supporting CUDA 12.4 or later. Other hardware/runtime combinations have not
been established by this release validation.

[`examples/anvil_block.py`](../../examples/anvil_block.py) reads the supplied
mesh, assembles the stable Neo-Hookean rest Hessian and lumped mass, constructs
six rigid constraints and computes 20 elastic modes. It imports solver APIs
only from `warpack`; no benchmark imports or reference eigensolutions are needed.
`--modes-out build/anvil-block.npz` optionally exports the 20 physical displacement
fields, vertices, tetrahedra, nodal mass and eigenvalues after the solve. This
file has no boundary-face/rendering metadata; the README's existing rendering
recipe and v0.1.3 assets remain available.

For caller-owned FP64 `warp.sparse` matrices, the essential setup is:

```python
import warp as wp
from warp.optim import linear
from warpack import BatchedCGPreconditioner, BatchedSparseOperator, BlockLOBPCG

# A = M^(-1/2) K M^(-1/2), shifted = A + 100 I, both compact 3x3 BSR.
# rigid contains six orthonormal rows in these mass-normalized coordinates.
factor = linear.FSAI(
    shifted, max_row_size=32, max_step_size=3, apply_lanes=8, factor_dtype=wp.float32
)
preconditioner = BatchedCGPreconditioner(
    shifted,
    24,
    preconditioner=factor,
    tol=0.01,
    maxiter=25,
    working_dtype=wp.float32,
    fsai_layout="columns",
    matrix_layout="columns",
)
solver = BlockLOBPCG(
    BatchedSparseOperator(A),
    20,
    24,
    constraints=rigid,
    preconditioner=preconditioner,
    tol=1e-8,
    gram_chunk=4096,
    symmetric_products=True,
    fused_updates=True,
    paired_rotation=True,
    reuse_operator_images=True,
    search_bucket_size=4,
    keep_history=True,
    preconditioner_bucket_size=4,
)
graph = solver.capture(200)
wp.capture_launch(graph)
# Consume solver.eigenvalues/eigenvectors on device. After synchronization,
# require status == 0 and converged == 20 before accepting the result.
```

The example supplies the benchmark's explicit random start for reproducibility.
The snippet uses the solver's default start. These settings are tuned for Anvil;
shift, block width, factor fill and iteration budgets are not universal defaults.
Generalized SPD mass matrices may instead be supplied with `mass=...` to
`BlockLOBPCG`; arbitrary singular or indefinite mass matrices are outside that
solver's contract.

## Contracts and review

- Outer arithmetic is FP64 Warp. Inner CG is upstream Warp, with independent
  per-RHS coefficients and tolerances; the Anvil setting uses FP32. It is
  truncated CG preconditioning, not a fixed exact inverse for shift-invert.
- Setup allocates and synchronizes; FSAI construction and constraint validation
  are outside capture. The complete recorded solve, active-width selection and
  acceptance checks run on device. The release Anvil graph contains no HOST
  nodes and only device-to-device memcpy nodes.
- Replays read current matrix/constraint/start values at fixed topology and
  fixed storage identities. FP32 working matrix values refresh on device.
  The caller must maintain or rebuild factors when coefficients change.
- Keep input arrays, solver and factors alive through graph execution. Solver
  instances and shared-width CG variants own mutable scratch and cannot run
  concurrently. Bucket preallocation costs memory: about 4.45 GB device free
  memory decrease through setup/capture in the recorded Anvil run, excluding
  original fixture storage; this is not a peak-memory measurement.
- Successful residual/count status does not certify global spectral
  completeness from an arbitrary invariant starting block. Repeated-mode
  subspace tests and independent Anvil spectrum comparisons are included.
- Eager `solve(steps)` now reports the actual fixed iteration budget (#125).
  Invalid batched widths, budgets, tolerances and block-width mismatch are
  rejected during setup. Supplied upstream preconditioner shape/device mismatch
  is also rejected before application (#126). A weak owner reference avoids a solver/workspace
  ownership cycle introduced by preallocated search branches.

The release review was performed by the implementing agent, not an independent
reviewer. It covered the numerical promotion diff, replay freshness, graph
control, constraint-image transformations, shared scratch/ownership, metadata,
optional-dependency boundaries, packaging and documentation. The review and
validation evidence is recorded in [the release report](../../results/release_v0_2_0/README.md).

## Deliberately deferred

The known compact nonsymmetric requested-spectrum gap (#104), strict generic
pencil recovery (#123), large iterative/interior performance work, left and
infinite eigenmodes, unsupported precisions/interfaces, and upstream CuPy
failures remain tracked. cuDSS still has small vendor metadata HtoD transfers
(#29), and its older Anvil direct-solve control remains about four times faster
than this pure-Warp block path (#15). No claim is made that all issues are fixed.

The release contains Python wheel and source distribution artifacts. Large mesh,
GIF and Blender showcase assets remain available from
[v0.1.3](https://github.com/alecjacobson/warpack/releases/tag/v0.1.3).
